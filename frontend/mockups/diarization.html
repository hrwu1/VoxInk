Speaker diarization

Three ways to surface diarization in the recorder. All five job states are shown for each, so the least pleasant ones — failed and stale — get judged alongside the happy path rather than after it ships.

Mockup only. This file is outside every build root and imports nothing from the app. No production component has been touched. Pick one and I'll implement it.

Alternative A — a control in the recorder card most discoverable

A row directly under Save audio, mirroring that control exactly, so the dependency between them is visible: diarization needs retained audio, and here the two sit together. It is the only option where a user who has never heard of the feature will find it. The cost is permanent vertical space in the recorder, spent on something that does nothing until after Stop.

Alternative B — a chip in the transcript header least intrusive

A chip beside the existing language chip, plus speaker labels on the caption lines themselves. This puts the information where the answer actually is — next to the words — and costs no layout when diarization is off. The weakness is discovery: nothing advertises the feature, so it has to be enabled somewhere else, and an unlabelled line needs to explain its own blankness.

Alternative C — a notice strip below the transcript clearest failures

A strip that appears only when there is something to say, and disappears when there is not. It has the most room for the states that need an explanation and an action, and it never competes with the transcript for attention while recording. The cost is that it enters and leaves the layout, which shifts content, and like B it needs the opt-in to live somewhere else.

Shared by all three. Labels read Speaker 1, not MIC_SPEAKER_00: the underlying identifier is session-local and anonymous, and showing its raw form would suggest a durable identity that deliberately does not exist. Nothing claims a name.

Unlabelled lines stay unlabelled. Roughly one line in seven is expected to be too ambiguous to attribute, so every alternative has to make a blank line look deliberate rather than broken — that is what the third caption in B is testing.

No filenames appear anywhere. The UI shows a state and an action; the service reports which artifacts exist. No client constructs speaker-turns.json for itself.
